## 本週四大主軸

### 主軸 1：Agentic Engineering 的學科化

W19 最重要的線索。五篇來源從不同角度確認「agent 工程已從『調 prompt 的手藝』升格為『有方法論的工程學科』」：

| 來源 | 貢獻層級 | 核心論點 |
|------|---------|----------|
| [[src-mast]]（MAST 論文，EMNLP 2025）| 學術量化 | 多 agent 失敗 14 模式 / 3 類，整體失敗率 41-86.7%；FC1 系統設計 51.7%——**設計問題壓倒模型能力問題** |
| [[src-karpathy-sequoia-ascent-2026]]（Karpathy Sequoia）| 系統框架 | Software 3.0 / Vibe Coding raise floor vs Agentic Engineering raise ceiling / Jagged Intelligence / Hire by adversarial multi-agent project |
| [[src-armin-agent-design-hard]]（Armin）| Hands-on 細節 | SDK 選擇、cache points 配置、reinforcement injection、virtual fs、output tool、模型選擇、**testing & evals 仍是最難解的問題** |
| [[src-anthropic-managed-agents]]（Anthropic）| 產品化 | Managed Agents（cloud-hosted agent APIs）；「build with what we ship」 |
| [[src-graphify]]（graphify）| 工具化 | codebase → knowledge graph 跨 17 平台 skill；[[LLM Wiki]] 模式自動化版 |

**收斂點**：所有來源都指向「人類仍需設計 spec、督導 plan、寫 test、建 eval loop」——Karpathy 的「Agent 負責填空，你負責判斷該畫哪些空格」是這個收斂的最佳一句話。

⭐ **元層級事件**：Karpathy 在 Sequoia 對 founders 把 [[LLM Wiki]] 列為「以前不可能、現在自然」的代表案例——**本 wiki 專案正是他向矽谷推銷之方法論的具體實踐**。graphify（46k stars）是同模式在 codebase 場景的產品化證據。

### 主軸 2：「人類員工 → AI 員工」轉型的外部訊號

W19 外部世界出現一組互相呼應的訊號：

- **HN 5/8 #7：[[Cloudflare]] 裁員 20%（1,069 分）**——與 HN 5/6 #5「Cloudflare agents 可建帳號 + 買域名 + 部署（518 分）」形成戲劇性反差：同一家公司，一邊裁人一邊讓 agent 接手
- **PH 5/7 #2：Claude Agents for Financial Services（173 分）**——[[Anthropic]] 把 agent 推進金融行業（KYC / pitches / closing books），直接替代分析師工作
- **PH 5/7 #1：FlowMarket「AI agents 之間生成 B2B deals 的 socialnet」**——agent-to-agent 商業層，連「業務開發」都 agent 化
- **Karpathy Sequoia「Hiring should change」**——面試該是「給大專案讓 adversarial agents 攻擊」，不是 leetcode

→ 這條線索與 wiki 既有 [[src-Code Review已死]] / [[AI 品質共謀]] / [[Multi-Agent 失敗分類學]] 形成「agent 接手 → 但 agent 會失敗 → 需要新驗證紀律」的閉環。
