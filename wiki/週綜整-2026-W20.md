## 本週五大主軸

### 主軸 1：⭐「多 agent 鏈式誤差」三來源匯流（W20 最重要綜整發現）

本週三篇來源從**完全不同的層次**指向同一結論——結構性多 agent 會製造鏈式、複合放大的誤差：

| 來源 | 層次 | 核心論點 | 機制 |
|------|------|---------|------|
| [[src-mast]]（既有，學術）| 量化 | 多 agent 失敗 41-86.7%，FC2 跨 agent 對齊 31.35% | 14 失敗模式統計 |
| [[src-雷蒙-不需要-agent-team]]（個體）| 理論 | 個體不需結構性 multi-agent；Conway's Law 讓產出長成組織形狀 | Brooks's Law（溝通成本 n² 增長）+ Conway's Law + Coase 交易成本 |
| [[src-codex-代理人桌面作業系統]]（企業）| 實證 | KPI 儀表板「源頭 3% 誤差會讓下游全歪」 | 飲料店比喻：3% POS 誤差 → 三層代理人鏈複合放大 → 庫存全錯 |

**收斂洞察**：三者都指出「多 agent 鏈的誤差不是線性增加，而是複合放大」。雷蒙提供「為何不要結構性切分」的理論（Conway/Brooks），Codex 提供「即使要用也要嚴控源頭誤差」的實證（3%→全歪），MAST 提供量化背書。**這是對 [[Multi-Agent 失敗分類學]] 的三維強化**。

> 與 W19 主軸呼應：W19 確立「agent 會失敗，需新驗證紀律」，W20 補上「失敗如何在鏈中放大」的微觀機制。

### 主軸 4：CLAUDE.md / agent 工程方法論的官方化與規則化

三篇文章同指「CLAUDE.md 是 agent 工程的核心契約」：

→ **「agentic technical debt」是 W20 新概念**：每次讓 AI 從零猜架構導致「每模組能跑但整體無一致邏輯」——CLAUDE.md 是解方。對應使用者全域 CLAUDE.md（本就源自 forrestchang 4 規則）。
